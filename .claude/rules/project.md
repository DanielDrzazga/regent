# Regent — kontekst projektu

- Regent to narzędzie programisty łączące framework SDD i pomysły z OpenRig. Rozszerzenie na inne dziedziny („abstrakcja”) jest odłożone na później.
- Źródło prawdy o zakresie: plan produktu `~/_Private/regent-notes/Harness — wizja produktu.md` (zasady, model pojęć, etapy MVP, otwarte pytania). Zapis wywiadu, z którego wyrósł: `vision.md` w tym samym katalogu. Oba są poza repo, bo repo jest publiczne; tylko na Macu Daniela. Przed propozycją architektury lub zakresu przeczytaj plan produktu, a po kontekst wypowiedzi sięgnij do sekcji 16–18 wizji; na maszynie bez tych plików zapytaj. Treści planu (limity, maszyny, praca) nie przenoś do repo.
- Harness to warstwa runtime Regenta, nie osobny produkt: jedno repo, plugin to przepis SDD i adapter (hooki, statusline), stan i polecenia to komponent w `tools/`, a `regent-watch` staje się jego TUI.
- Punkty oznaczone w wizji jako `[delegowane]` rozstrzygają agenci analityczni — nie dopytuj o nie ponownie. Punkty `[interpretacja]` nie są ustaleniami.
- Repo nie pracuje w cyklu SDD (bez `ai/`). Zmiany idą lekką ścieżką: gałąź, plan z checklistą w `docs/plans/<nazwa>.md`, bramka `bash scripts/framework-lint.sh` + `claude plugin validate .` (jedyne dozwolone ostrzeżenie: brak `version`) i smoke. Mechanikę robi sesja główna, bez subagentów.
- Etap: plugin gotowy w repo (`plugin-import`, `plugin-hooks`, `retire-home-sdd` zakończone), etap 1 planu produktu — rdzeń zadań (`task-core`) — w `main` od 2026-09-29. **Źródłem prawdy frameworka SDD jest to repo** — każda zmiana SDD trafia tutaj. Stary framework w `~/.claude` jest na Macu wyłączony (2026-09-30): `CLAUDE.md`, `commands/` i `agents/` leżą w `~/.claude/sdd-wylaczone-2026-09-30/` — nic z niego nie usuwaj ani nie rozwijaj, a `scripts/` zostaje na miejscu. Plugin działa we wszystkich sesjach z terminala przez alias `claude --plugin-dir` w `~/.zshrc` (na żywo z klonu — wygrywa z instalacją), a w aplikacji desktop z lokalnego marketplace `regent` (katalog repo, plugin w zakresie `user`), który trzyma kopię z commita: po każdym merge'u do `main` `claude plugin marketplace update regent && claude plugin update regent@regent`, potem nowa sesja w desktopie (albo restart aplikacji). `.claude-plugin/marketplace.json` jest lokalny i nie trafia do repo — plugin **nie jest publikowany w żadnym marketplace do czasu ukończenia**. Następny krok: tydzień sprawdzenia etapu 1 (2026-09-29 – 2026-10-06; kryteria i punkt odniesienia w `docs/plans/task-core.md`, sekcje „Sprawdzenie etapu” i Przebieg sesji 4), potem plan etapu 2.
- Komunikacja i dokumenty po polsku, z pełną polską ortografią. Identyfikatory i nazwy techniczne w oryginale.
